# 2026-07-31 工作日志

## 验证码识别: 修复 test.png 的 'x' 漏读问题

### 问题
- `images/test.png` 肉眼识别为 `xf4y4`，程序输出 `f4y4`(漏x) 或 `if4y4`(x误读为i)
- 根因: 图片有密集竖直干扰线 + `x` 与 `f` 笔画粘连 + `x` 笔画较淡

### 解决方案
1. **新增"深增强"预处理变体** (`main.py`):
   - `gamma=3.7, upscale=4, denoise=3, bg_whiten=0`
   - 高gamma大幅提亮暗笔画(恢复淡色x)，高放大增加细节，不提白避免抹掉淡笔画
   - beta模型在此变体下能正确识别 `xf4y4`

2. **改进 `pick_best` 择优逻辑** (`ddddocrImg.py`):
   - **排他性子序列支持**: 对每个唯一短结果(2≤len<L)，检查它是哪些L长候选的子序列。仅匹配一个→排他支持(权重1.5)；匹配多个→模糊支持(权重0.3)。如 `x4y4` 仅是 `xf4y4` 的子序列→强力支持 `xf4y4`
   - **滑动窗口**: 对长输出(>L)提取所有L长连续子串参与投票，边缘裁剪越少权重越高
   - **逐字符降权**: "逐字符"结果已知噪声大，投票权重降为0.5
   - **自动推断长度**: 未指定 `--length` 时，用最长候选长度作为期望长度，让高阶择优也生效

### 测试结果
| 图片 | 期望 | 修改前 | 修改后 |
|------|------|--------|--------|
| test.png --length 5 | xf4y4 | if4y4 | xf4y4 |
| test.png (无length) | xf4y4 | x4y4 | xf4y4 |
| test2.jpg | kdqu | kdqu | kdqu |
| xf4y4_test.png | xf4y4 | - | xf4y4 |
| phhxx_test3.png | phhxx | - | phhxx |

### 关键发现
- `bg_whiten=235`(默认)会抹掉淡色笔画，是x被漏读的元凶之一
- ddddocr beta模型在高gamma(3.5-4.0)+高放大(4)下能识别出x
- 排他性子序列支持能有效解决"少数正确结果被多数错误结果淹没"的问题
