骨干 CNN 说明

      
    

    

      
骨干 CNN 是模型的特征提取前端，后面统一接 双向 LSTM → CTC 解码。骨干只负责"从图里抽出有效特征"，其质量直接决定识别上限。

      

        
骨干结构特点

        
ddddocr_beta21 层稠密 Conv + hswish + 残差，输入高度固定 64与 ddddocr 新版 common.onnx 同款；唯一支持迁移学习（从预训练权重微调）

        
ddddocr7 层 Conv（16→128 通道）+ ReLU + MaxPool最简经典 CRNN 骨干，容量最小

        
effnetv2_sEfficientNetV2-Small，6 个 stage 的 MBConv + SE现代轻量骨干，容量小→中

        
effnetv2_mEfficientNetV2-Medium，7 个 stage，SE 更密集（最大通道 512）容量最大、理论上限最高，也最慢、最易在小数据上过拟合

        
mobilenetv3_sMobileNetV3-Small，11 个 MBConv Block + hswish + SE极致轻量，最大通道 96，速度最快

      

      
关键：只有 ddddocr_beta 有预训练权重

      
项目内置迁移逻辑（勾选「迁移学习初始化」）只支持 ddddocr_beta 且 输入高度 = 64：会把 ddddocr 官方 common.onnx 的骨干 + LSTM 权重直接载入，只重新训练 fc 分类层。其余 4 个骨干项目内无预训练来源，选择后为随机初始化从零训练。

      

        建议：数据量小时（几百到一千张），迁移的 ddddocr_beta 通常明显优于任何从零训的模型——这也是当前 apple 批次（批跑一致率 ~0.89）的选型。若想换骨干实验，从零训首选 effnetv2_s 或 mobilenetv3_s（更稳妥）；effnetv2_m 需要更大数据量 + 增广才可能体现优势。判断标准以「全量批跑匹配率」为准（验证集数字偏乐观）。
